tiny-paper display: sketch

Draw with the mouse, a pen or a finger. Each stroke goes to the panel as a partial update of the area that changed; the drawing here is what the panel is brought to.

This browser cannot reach a USB device (no Web Serial). Use Chrome or Edge on a computer. See the page work without a device.

Plug the display in with a USB data cable, press Connect and pick its port ("USB JTAG/serial debug unit").

This page needs the display firmware on the device: install it on the Flash page, then come back.

Debug

For trying how the panel is driven and handing the result to someone else: paste a configuration, press Apply, draw, then copy the Report and paste it back. Nothing here is stored in the device (it lasts until the device restarts) and nothing is kept by this page across a reload except the text below.
{ "tuning": { ... }, "sketch": { ... } }. tuning: the panel's drive keys (TRMNL X), or "defaults"; the keys are in the protocol page, "Tuning". sketch: depth (1, 2 or 4: the bit depth strokes go out at, where the device does partial updates at it), mode (auto, partial, full or another mode the device lists), full_after (a full refresh after n partial sends, 0 never), erase (auto, partial or full: what a send that makes pixels lighter does), test: a pattern the page draws and sends by itself after a full refresh of the blank panel, the same every time: grays one bar for each level from black to white, each its own partial update (the white bar changes nothing, so it is not sent); lines thin, medium and thick black lines, six partial updates; box a mid gray box, then a white box inside it, two partial updates.

This device has no panel tuning: the tuning part is refused, the sketch part works.
