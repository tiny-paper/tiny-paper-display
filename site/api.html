USB display protocol, version 1

The whole API of the display firmware (firmware/display): a board as a plain display driven over its USB cable. Three things: hello, show, clear. Vectors: vectors/usb-display.json (gen_usb_display.py), replayed by firmware/components/usbdisp/test/test_usbdisp.c and python/tests/test_display_fw.py. Code: firmware/components/usbdisp.

Frames

As the link protocol (link-protocol.md "Frame"): USB CDC byte stream, any baud rate.

OffSizeField
02sync A5 5A
22len u16 LE: payload length, 0..6144
41seq 1..255, chosen by the host
51cmd; the answer has cmd | 0x80 and the same seq
6lenpayload: one CBOR map with text keys in the order given below (len = 0 is read as {})
6+len2CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF) over bytes 2 .. 6+len-1, u16 LE

Device to host, bytes outside frames are log text (# ...\n, never A5): skip to the next A5 5A. A frame with a bad CRC gets no answer. One request at a time. Half a frame with no further byte for 2 s is forgotten. No retransmit cache: after a lost answer send hello and start the picture again.

Commands

cmdNameRequestAnswer
0x01helloany map (the app's { proto: 1, app: tstr } is fine){ proto: 1, project: "display", fw: tstr, board: tstr, w: uint, h: uint, depths: [uint], colors?: [tstr], max_payload: 6144, max_png: uint, chunk: 4096 }
0x08show_begin{ size: uint } the PNG's bytes{ chunk: 4096, next: 0 }; replaces an open transfer
0x09show_chunk{ off: uint, data: bstr }{ next: uint }. off must be next; the first chunk holds at least the PNG's first 29 bytes and is checked at once (size, depth)
0x0Ashow_end{}{ depth: uint, ms: uint, warn?: tstr } after the full refresh. ms: time of the panel work
0x0Bclear{}as show_end: the panel white, full refresh

project: "display" tells this firmware from the app, whose hello has no project and which answers 0x08..0x0B with UNKNOWN_CMD. board: trmnl_og, picpak, trmnl_x. depths: the gray bit depths taken. colors (["black","white","red","yellow"], PicPak): the panel's own colors. warn: the driver reported a refresh in less time than the panel needs (SPI panels: under 300 ms): look at the panel.

The picture

Exactly the panel's width and height, shown as given: no scaling, no dithering, no rotation on the device.

PanelPNG takenShown as
gray (trmnl_og, trmnl_x)grayscale (color type 0), bit depth 1, 2 or 4 when in depthsits levels, 0 black
colors (picpak)grayscale 1 bit; or indexed (color type 3, up to 8 bit) whose used entries are 000000, ffffff, ff0000, ffff00black, white, red, yellow

Not taken: 8 or 16 bit, RGB, alpha, interlaced, an indexed PNG on a gray panel. Chunk CRCs and the Adler sum are not checked (the link's CRC covered the bytes); ancillary chunks are skipped.

Refusals

{ err: uint, msg: tstr (<= 120 bytes), detail?: map }. A refusal never changes the panel.

errNameWhen
1UNKNOWN_CMDany other cmd 0x01..0x3F
2BAD_REQUESTpayload not one CBOR map, a key missing or of the wrong type, a first chunk under 29 bytes
3BUSYthe panel is refreshing: detail { retry_ms: 2000 }; hello is still answered. trmnl_x: requests wait for the refresh instead
10IOthe panel driver failed (msg says at which step)
11SEQUENCEno transfer open, off not the next offset, or show_end before all bytes: detail { next: uint }
13TOO_LARGEsize over max_png, or more bytes than size (the transfer is dropped)
14NOMEMno memory for the PNG, the frame or the decoder
32NOT_PNGno PNG signature, or under 57 bytes
33WRONG_SIZEnot the panel's width and height (msg has both)
34DEPTHa color type, bit depth or color the panel does not show; interlaced
35BAD_PNGdamaged or cut short

Bounds

ItemValue
max_pngrows of the deepest PNG taken, a filter byte each, plus 4096: 100576 (trmnl_og), 124396 (picpak), 1319644 (trmnl_x)
Memorythe PNG, then the frame (w * depth / 8 * h) and the decoder (<= 32 KiB window, two rows); the PNG is freed before the refresh
Quiet transferdropped 10 s after its last request, memory freed
Cable pulledthe device restarts from deep sleep: no transfer state survives; the panel keeps the last picture shown
